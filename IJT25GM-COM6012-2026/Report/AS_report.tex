Each institution domain is extracted by first splitting each hostname using the full stop delimiter.
For example, the Sheffield hostname, \texttt{www.shef.ac.uk}, is split into \texttt{["www", "shef", "ac", "uk"]}.
The final three labels are concatenated together, resulting in \texttt{shef.ac.uk}, which represents the institution domain.
Different hosts from the same institution (\texttt{cs.shef.ac.uk}, \texttt{www.shef.ac.uk}, et cetera) are grouped together, allowing requests to be aggregated at the institution level.
The implementation of this method in Spark is demonstrated in Listing \ref{lst:institution_extraction}.
\begin{lstlisting}[language=Python,
                   caption={Institution domain extraction and aggregation applied to UK academic hosts. The \texttt{extract\_domain} function can be applied to other hostname suffixes.},
                   label={lst:institution_extraction}]
def extract_domain(data, suffix: str, alias: str):

    filtered_hosts = data.filter(col("host").endswith(suffix))

    split_host = split(col("host"), "\\.")

    institution_domains = filtered_hosts.select(
        col("host"),
        col("timestamp"),
        concat_ws(".",
                element_at(split_host, -3),
                element_at(split_host, -2),
                element_at(split_host, -1)
        ).alias(alias)
    )

    return institution_domains

academic_domains = extract_domain(logs, ".ac.uk", "institution")

academic_counts = academic_domains \
    .groupBy("institution") \
    .count() \
    .withColumnRenamed("count", "total_requests")
\end{lstlisting}

%%%%%% TASK B
A Poisson regression model uses the training and validation sets to tune the \texttt{regParam} hyperparameter over the values [0.001, 0.01, 0.1, 1, 10, 100, 1000], each with five random subsets that sample 80\% of the training set.
The random seeds used are 17677, 17678, 17679, 17680, and 17681 (using student registration number 250117677).

The resulting mean validation MSE of each \texttt{regParam} value is shown in Figure \ref{fig:poisson_mean_mse}.
The optimal value is \(\texttt{regParam}=0.001\), which has the lowest mean validation MSE (\(813\,706.18 \pm 237.58\)).
Increasing \texttt{regParam} from 0.001 to 0.01 and 0.1 causes a sharp increase in MSE, which plateaus for larger values.
This suggests that stronger regularisation causes the Poisson regression model to underfit.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
%%%%%% TASK C
The median value of \texttt{all\_motor\_vehicles} in the training set is 235.0.
This value is used as the threshold between low and high traffic, allowing a binary target column, \texttt{traffic}, to be created.
A logistic regression model is then trained on the processed training set.
The same \texttt{regParam} values as in Figure \ref{fig:poisson_mean_mse} are tested, along with \texttt{elasticNetParam} values [0.0, 0.2, 0.5, 0.8, 1.0]. 
Five random training subsets are created to record the mean validation accuracy for each combination of \texttt{regParam} and \texttt{elasticNetParam}, which is shown in Figure \ref{fig:logistic_mean_acc}.

The optimal combination is \(\texttt{regParam}=0.001\) and \(\texttt{elasticNetParam}=0.0\), as this results in the highest mean validation accuracy of 0.63.
Figure \ref{fig:logistic_mean_acc} shows that all \texttt{elasticNetParam} values give similar mean validation accuracy for small regularisation strengths, particularly \(\texttt{regParam}=0.001\) and 0.01.
However, performance drops sharply when \texttt{regParam} increases to 0.1, consistent with Figure \ref{fig:poisson_mean_mse}.
The exception is \(\texttt{elasticNetParam}=0.0\), which remains stable until \(\texttt{regParam}=10\), indicating that pure L2 regularisation is less sensitive to increasing \texttt{regParam} than elastic net or L1-heavy regularisation.

Using the optimal \texttt{regParam} and \texttt{elasticNetParam} values, the logistic regression model is retrained on the combined training and validation sets before being evaluated on the test set, achieving an accuracy of 0.6404.
The final learned model coefficient vector is provided in the submitted file \texttt{Q2/Q2\_output.txt} (lines 257--312).


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
%%%%%% TASK D
One interesting observation is that both regression models perform best with very weak regularisation.
In Figure \ref{fig:poisson_mean_mse}, the Poisson regression validation MSE is lowest at \(\texttt{regParam}=0.001\), and increases sharply as \texttt{regParam} becomes larger, suggesting that strong regularisation results in underfitting.
A similar pattern is observed in Figure \ref{fig:logistic_mean_acc} for logistic regression, where accuracy is highest for small \texttt{regParam} values and then drops when regularisation becomes stronger.
This suggests that the processed traffic features contain useful predictive information, but stronger regularisation suppresses the model coefficients too heavily and reduces performance.

\textbf{Observation 1:}
The second ALS setting demonstrates worse performance for all three training splits, despite being designed to improve upon the first ALS setting.
This could be due to the increased \texttt{rank} parameter making the model more complex, with insufficient values of \texttt{regParam} and \texttt{maxIter} to improve generalisation on future ratings.
For a movie website such as Netflix, this shows that more complex recommendation models are not necessarily better, and that model changes should be carefully evaluated before deployment.

\textbf{Observation 2:}
Drama and comedy are the two most common genres among highly rated movies in the largest cluster for all three training splits, as shown in Table \ref{tab:q4_top_genres}.
This could be because they are broad umbrella genres and could be attributed to smaller sub-genres such as dark comedy, romantic comedy, et cetera.
It may also indicate the presence of mainstream preferences in the largest user group, rather than highly specialised taste profiles.
This could be useful to a movie site such as Netflix in identifying general audience preferences and prioritising recommendations that are broadly appealing.
Small clusters could still be used to provide more personalised suggestions.
